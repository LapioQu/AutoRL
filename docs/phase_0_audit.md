# Фаза 0: аудит і каркас проєкту

Ця нотація фіксує межі та результат Фази 0 згідно з `текст.txt` і `ТЗ_AutoRL_інтегрована_редакція_вимог.md`.

## Мета фази

Підготувати репозиторій до контрольованої поетапної розробки без передчасного переходу до доменних сутностей, середовищ RL, API або UI-логіки.

## Що має бути готово у Фазі 0

- `pyproject.toml` для пакування і запуску тестів;
- базовий `README.md`;
- `src`-layout з пакетом `src/autorl`;
- порожні пакети шарів `application`, `domain`, `infrastructure`, `interfaces`;
- інтерфейсні пакети `api`, `cli`, `ui`;
- мінімальна команда import smoke-check;
- тести, які перевіряють імпорт каркаса.

## Межі фази

У Фазі 0 не реалізуються:

- доменні моделі експериментів;
- конфігурації сценаріїв;
- RL-середовище;
- метрики, utility, LCB, Stay/Switch;
- SQLite-сховище;
- FastAPI endpoint-и;
- Streamlit сторінки.

## Мінімальні перевірки

Очікувані команди для завершення Фази 0:

```bash
python -m pytest
python -m autorl
```

Критерії успішності:

- усі smoke-тести проходять;
- пакет `autorl` імпортується без помилок;
- CLI-ентрипойнт повертає стабільне повідомлення `AutoRL package import OK`.
